# **VBA開発自動化 詳細ロードマップ**

「VBA開発自動化 統合戦略プラン」で定義したゴールを実現するため、具体的なタスクと成果物を時系列で定義した開発ロードマップを以下に示します。本ロードマップは4つのフェーズで構成され、最初の**フェーズ1でMVP（実用最小限の製品）を完成させる**ことを目標とします。

## **ロードマップ全体像**

| フェーズ | 主要目標 | 期間（目安） |
| :---- | :---- | :---- |
| **Phase 1** | **MVP: 基本ビルド自動化基盤の構築** | **1～2週間** |
| **Phase 2** | **テスト自動化と開発体験の向上** | **2～3週間** |
| **Phase 3** | **プロセスの堅牢化とユーティリティ拡充** | **1～2週間** |
| **Phase 4** | **CI導入による完全自動化** | **2週間～** |

## **Phase 1: MVP \- 基本ビルド自動化基盤の構築**

**目標:** 手作業で最も時間のかかる「VBAコードのインポートとExcelファイルの生成」を完全に自動化し、ワンコマンドで実行できる基盤（MVP）を構築する。

| タスクID | タスク内容 | 詳細 | 成果物 |
| :---- | :---- | :---- | :---- |
| **1-1** | **環境構築とリポジトリ設計** | Gitリポジトリを初期化し、プランで定義された標準フォルダ構成 (src/vba, template, tools, build) を作成する。 | ・Gitリポジトリ\<br\>・標準フォルダ構造 |
| **1-2** | **テンプレートの準備** | 今後の開発の土台となるマクロ有効テンプレート (.xltm) を作成し、templateフォルダに配置する。 | ・template/BaseTemplate.xltm |
| **1-3** | **PowerShellビルドスクリプト開発** | **【本フェーズの中核タスク】**\<br\>1. テンプレートを複製してbuildフォルダに配置\<br\>2. src/vba内の全VBAファイル (.bas, .cls) をインポート\<br\>3. 参照設定（例: Scripting Runtime）をGUIDで追加\<br\>4. 成果物として.xlsmファイルを保存\<br\>5. 実行後、Excelプロセスが残らないよう後処理を徹底 | ・tools/Build-VbaProject.ps1 |
| **1-4** | **実行ランナーの作成** | 開発者がPowerShellを意識せずに済むよう、ダブルクリックするだけでビルドスクリプトを実行できる簡単なバッチファイルを作成する。 | ・build.bat |
| **1-5** | **手順書の整備** | 開発環境の初期設定（VBAプロジェクトへの信頼アクセス許可など）と、build.batの実行方法を記述した簡単なドキュメントを作成する。 | ・README.md |

**このフェーズ完了時の状態:** 開発者はVBAコードをsrc/vbaフォルダに配置し、build.batを実行するだけで、コードが組み込まれた.xlsmファイルを入手できるようになる。

## **Phase 2: テスト自動化と開発体験の向上**

**目標:** MVPで構築したビルドプロセスにテスト実行を組み込み、コードの品質を担保する仕組みを構築する。また、設定を外部ファイル化し、保守性を向上させる。

| タスクID | タスク内容 | 詳細 | 成果物 |
| :---- | :---- | :---- | :---- |
| **2-1** | **VBAテストハーネスの設計・実装** | テンプレート (.xltm) 内に、全てのテストコードを統括実行するTestRunnerモジュールを作成する。テスト結果を特定のシートに書き出す機能も実装する。 | ・テスト実行機能を持つBaseTemplate.xltm |
| **2-2** | **ビルドスクリプトへのテスト実行組込** | Build-VbaProject.ps1を改修し、VBAインポート後にTestRunnerマクロを自動実行する処理を追加する。テストが失敗した場合はビルドが失敗するように制御する。 | ・テスト実行機能が追加されたBuild-VbaProject.ps1 |
| **2-3** | **設定ファイル(manifest)の導入** | インポートするファイルリスト、追加する参照設定、実行するテストマクロ名などをconfig.jsonのような設定ファイルに分離する。PowerShellはこれを読み込んで動作するように改修する。 | ・config/manifest.json\<br\>・設定ファイルを読み込むよう改修されたスクリプト |

**このフェーズ完了時の状態:** build.batを実行すると、ビルドとテストが連続して実行され、テストが失敗した場合は即座に検知できるようになる。

## **Phase 3: プロセスの堅牢化とユーティリティ拡充**

**目標:** 自動化プロセスをより安定させ、開発を補助する便利なユーティリティ機能を追加する。

| タスクID | タスク内容 | 詳細 | 成果物 |
| :---- | :---- | :---- | :---- |
| **3-1** | **セキュリティ設定の自動管理** | ビルドスクリプト実行時に「VBAプロジェクトへの信頼アクセス」設定を一時的に有効化し、終了時に元に戻す処理をPowerShellで実装する（レジストリ操作）。 | ・セキュリティ設定を自動管理するスクリプト |
| **3-2** | **VBAコードのエクスポート機能** | 既存の.xlsmファイルからVBAコードをsrc/vbaフォルダに一括エクスポートするExport-VbaCode.ps1スクリプトを作成する。これにより、Excel上で直接修正したコードも安全にソース管理できる。 | ・tools/Export-VbaCode.ps1 |
| **3-3** | **テストレポート機能の強化** | テスト結果をCSVやJSON形式で出力し、ビルド日時や実行環境などのメタ情報も記録するようにTestRunnerとPowerShellを改修する。 | ・構造化されたテストレポートファイル |

**このフェーズ完了時の状態:** 手動でのセキュリティ設定変更が不要になり、双方向のコード同期が可能になるなど、開発体験が大幅に向上する。

## **Phase 4: CI導入による完全自動化**

**目標:** Gitへのpushをトリガーに、これまで構築したビルド・テストプロセスを完全に自動で実行するCI（継続的インテグレーション）環境を構築する。

| タスクID | タスク内容 | 詳細 | 成果物 |
| :---- | :---- | :---- | :---- |
| **4-1** | **ローカルCI環境の構築** | Gitのpre-pushフックなどを利用し、リモートリポジトリにpushする直前にローカルPC上で自動テストが実行される仕組みを導入する。 | ・Gitフックスクリプト |
| **4-2** | **CI/CDパイプラインの構築 (発展)** | GitHub Actions (Self-hosted runner) やJenkinsなどを利用して、特定のブランチにpushされると自動でビルド・テストが実行され、成果物が保存されるパイプラインを構築する。 | ・CIツールの設定ファイル (例: .github/workflows/build.yml) |

**このフェーズ完了時の状態:** コードの変更がリポジトリにマージされるたびに品質が自動で検証され、常に動作可能な成果物が生成される、近代的な開発フローが完成する。
