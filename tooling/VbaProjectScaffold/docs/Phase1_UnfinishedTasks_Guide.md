# Phase1 未実施タスク対応ガイド

## 0. 使い方
1. 各セクションの「概要」「決定すること」「手順」「成果物」「チェックリスト」を順に確認します。
2. 決定・作業が完了したらチェックリストの該当項目を `- [x]` に更新し、`docs/Phase1_ImplementationPlan.md` の対応項目もチェックします。
3. 不明点が出た場合は「関係者への確認事項」欄をもとに依頼者として判断／調整してください。

## 1. リポジトリ配置と環境整備
### 概要
ローカル環境および共有環境で同一のディレクトリ構成・ツール実行が再現できるようにします。

### 決定すること
- リポジトリをどこに配置するか（例: `C:\VBA-Automation`）。
- その他利用者が同じ手順で環境構築できるようにするための注意点。

### 手順
1. 代表環境（依頼者PC）で `C:\VBA-Automation` にフォルダを作成し、リポジトリをクローンまたは配置する。
2. `build.bat` が動作することを確認する（Excel を閉じた状態で実行）。
3. 実施手順を簡単なドキュメント（例: `docs/setup/EnvironmentSetup.md`）にまとめる。
4. 他端末で再現が必要な場合は手順に従って検証し、差異があれば手順に追記する。

### 成果物
- 環境構築手順書（フォルダ構成、依存ソフト、実行手順）。

### チェックリスト
- [ ] `C:\VBA-Automation` へリポジトリを配置した。
- [ ] `build.bat` の成功を確認した。
- [ ] セットアップ手順書を作成し共有した。

## 2. Excel マクロ有効化と信頼済み設定
### 概要
Excel がVBAを実行できるように、マクロ有効化と VBA プロジェクトへの信頼設定を明文化します。

### 決定すること
- Excel のマクロ警告にどう対応するか（組織ルールがあれば準拠）。
- 信頼済み場所を登録するフォルダ。

### 手順
1. Excel を開き、`ファイル > オプション > セキュリティ センター > セキュリティ センターの設定` を開く。
2. 「マクロの設定」を「警告を表示してすべてのマクロを無効にする」にし、必要時に有効化できるよう手順化。
3. 「開発者用マクロの設定」で「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」にチェック。
4. 「信頼できる場所」にリポジトリフォルダ（例: `C:\VBA-Automation`）を追加。
5. 手順を `docs/setup/ExcelTrustSettings.md` といったドキュメントにまとめ、スクリーンショットを添付する。

### 成果物
- Excel 設定手順書（スクリーンショット付き推奨）。

### チェックリスト
- [ ] Excel のマクロ設定を確認し、推奨値を決定した。
- [ ] 信頼済み場所を登録した。
- [ ] 設定手順書を作成・共有した。

## 3. `config/build-config.json` の最終凍結
### 概要
ビルド設定（テンプレ・ソース・出力・ログ・バージョン情報）がチームで共通化されているか確認します。

### 決定すること
- 出力先パス・ファイル命名規則を最終決定する。
- バージョン情報の記録方針（デフォルトオーナーやメモのテンプレート）。

### 手順
1. 現在の `config/build-config.json` を確認し、必要な項目（`OutputPath`、`OutputFileName` など）が要件に合うか確認。
2. 出力ファイルを保管するフォルダを決め、必要なら `OutputPath` を変更。
3. 変更後、`build.bat` を実行して `.json` の設定で正しく成果物が生成されるか検証。
4. 設定を変更した場合は変更理由と最終値を `docs/config/BuildConfigNotes.md` などに記録。
5. 凍結後は `docs/Phase1_ImplementationPlan.md` でチェックを入れる。

### 成果物
- 最新 `config/build-config.json`
- 設定メモ（変更理由と最終値）

### チェックリスト
- [ ] 出力パス・命名規則を確定した。
- [ ] 修正後のビルド成功を確認した。
- [ ] 設定メモを作成した。

## 4. 環境別出力パス切替の方針
### 概要
共有ドライブなど環境ごとに出力先が異なる場合の対処方法を決めます。

### 決定すること
- 単一出力パスで十分か、環境変数や設定ファイルで切り替えるか。
- 必要なら `config/build-config.json` で環境キーを定義するか。

### 手順
1. 出力ファイルを共有する必要があるか確認。
2. 共有が必要であれば、環境ごとのパス一覧を作成。
3. 切り替え案を検討（例: `build.bat` に `/env` 引数を追加、または `config/environments/*.json` を読み分ける）。
4. 選択した方式を実装し、複数環境で `build.bat` を試験。
5. 関連ドキュメントを更新（使用手順に環境指定方法を追記）。

### 成果物
- 切替方式に関する設計メモ・実装（必要な場合）
- 手順書への追記

### チェックリスト
- [ ] 出力先の要件を確認した。
- [ ] 切替方式を決定した。
- [ ] 必要な実装・手順書更新を完了した。

## 5. マスターデータ管理フロー
### 概要
マスタシートのデータをどう保守するか決定します。

### 決定すること
- マスタデータを外部ファイルから読み込むか、手動編集とするか。
- 更新タイミング・責任者。

### 手順
1. マスタシートの用途（例: 区分コード、税率など）を整理。
2. 外部連携が必要か関係者と確認。
3. 外部ファイル連携する場合は `DataManager` に読み込みロジックを追加する仕様を検討。
4. 手動更新にする場合はテンプレート上に更新手順（例: 「○○を更新したらビルドを実行」）を追記。
5. 決定内容を `docs/operations/MasterDataPolicy.md` にまとめる。

### 成果物
- マスタ管理ポリシー文書
- 必要に応じてコード改修案

### チェックリスト
- [ ] マスタデータの利用目的を整理した。
- [ ] 連携方式を決定した。
- [ ] 手順またはコード改修方針を文書化した。

## 6. ログ保持ポリシーとローテーション
### 概要
`logs/` に蓄積されるログの保持期間と処理方法を定めます。

### 決定すること
- ログの保存期間（例: 30日）。
- ログの保管場所（ローカル／共有）と不要ファイル削除のタイミング。

### 手順
1. ログの重要度を確認し、最低限必要な保持期間を決める。
2. `OutputRetentionDays`（現在30日）を基本に、バッチまたは PowerShell スクリプトで期間超過ファイルを削除する仕組みを検討。
3. `tools/Build-VbaProject.ps1` に保守ロジックを追加するか、別途 `scripts/CleanupLogs.ps1` を作成。
4. 手順を `docs/operations/LogPolicy.md` にまとめる。

### 成果物
- ログ保守ポリシー文書
- 可能なら清掃スクリプト

### チェックリスト
- [ ] 保存期間を決定した。
- [ ] ローテーション処理の手段を決定・実装した。
- [ ] ポリシー文書を作成した。

## 7. 品質保証 (QA)
### 7.1 PowerShell 単体テスト
- [ ] Pester などを導入し、`tools/Build-VbaProject.ps1` の主要機能（設定読み込み、エラー時の終了コードなど）をテストする。
  1. `tools/tests/Build-VbaProject.Tests.ps1` を作成。
  2. 想定シナリオ（成功、テンプレ不在、参照追加失敗など）を網羅。
  3. `README` にテスト実行方法を追記。

### 7.2 Excel マクロ スモークテスト
- [ ] 手動チェックリストを作成（例: ボタン押下でメッセージが出るか、集計シート値が更新されるか）。
  1. `docs/tests/ExcelSmokeTestChecklist.md` を新規作成。
  2. ビルド直後の `.xlsm` を開いて検証する手順を書く。

### 7.3 自動エクスポート後の差分検証
- [ ] Git などで VBA モジュールに差異がないか確認する仕組みを設計。
  1. `scripts/CompareModules.ps1` で `build` 出力の VBComponents と `src/vba` を比較。
  2. 重要な差分が出た場合の対応フローを定める。

### 7.4 受入テスト実施
- [ ] 主要シナリオ（入力→集計→ログ出力）を手順書化し、テスト結果を記録。
  1. `docs/tests/UAT.md` にテストケース・結果欄を用意。
  2. 実施後に `Phase1_ImplementationPlan.md` の該当チェックを入れる。

## 9. 移行と展開
### 概要
本番展開のための準備項目を整理します。

### 手順の例
1. 既存 Excel から移行するデータの有無を確認。
2. 移行対象がある場合は `docs/deployment/DataMigrationPlan.md` を作成。
3. リリーススケジュールと通知テンプレ（メール・Teams 投稿）を `docs/deployment/ReleaseCommunicationTemplate.md` に作成。
4. 利用者向けトレーニング資料（操作説明、よくある質問）を `docs/training/UserTrainingSlides.pptx` 等として用意。
5. ロールアウト後のフォローアップ会議の日程と議題を決め、議事録テンプレを準備。

### チェックリスト
- [ ] データ移行の要否と手順を決定した。
- [ ] リリース通知テンプレートを作成した。
- [ ] トレーニング資料を用意した。
- [ ] フォローアップ計画を立てた。

## 10. 関係者への確認事項まとめ
| 項目 | 確認先 | メモ |
|------|--------|------|
| 共有ドライブの出力要件 | 利用部門 | 無しの場合は「不要」と記録 |
| マスタデータ更新責任者 | 利用部門 | 未定なら保留理由を明記 |
| ログ保持ポリシー | セキュリティ担当または依頼者判断 | 30日など具体数値 |
| 受入テストの合格基準 | 依頼者 | 「主要機能が評価N件通過」など |
| トレーニング対象 | 利用部門 | 人数と日程 |
