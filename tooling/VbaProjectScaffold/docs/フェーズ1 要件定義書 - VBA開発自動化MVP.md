# フェーズ1 要件定義書 - VBA開発自動化MVP

## 1. プロジェクト概要

### 1.1 プロジェクト名
VBA開発自動化基盤構築プロジェクト - フェーズ1（MVP）

### 1.2 目的
手作業で最も時間のかかる「VBAコードのインポートとExcelファイルの生成」を完全に自動化し、ワンコマンドで実行できる基盤を構築する。

### 1.3 背景
- LLMによるVBAコード生成は高速化したが、Excelへの組み込み作業は依然として手動
- 繰り返しの手作業によるヒューマンエラーのリスク
- 開発サイクルの遅延による生産性の低下

### 1.4 スコープ
#### 対象範囲
- VBAコードの自動インポート機能
- テンプレートからのExcelファイル生成
- 参照設定の自動追加
- ワンクリック実行環境の構築

#### 対象外範囲
- テスト自動化（フェーズ2で実装）
- CI/CD環境の構築（フェーズ4で実装）
- 複雑なUI操作の自動化

## 2. システム要件

### 2.1 機能要件

#### FR-001: リポジトリ構造の標準化
- 標準フォルダ構成の作成
  - src/vba: VBAソースコード格納
  - template: Excelテンプレート格納
  - tools: 自動化スクリプト格納
  - build: ビルド成果物格納
- Gitによるバージョン管理

#### FR-002: テンプレート管理
- マクロ有効テンプレート（.xltm）の作成と管理
- 基本的なVBAプロジェクト構造の事前定義

#### FR-003: ビルドプロセスの自動化
- テンプレートファイルの複製
- VBAモジュールの自動インポート
  - 標準モジュール（.bas）
  - クラスモジュール（.cls）
- 参照設定の自動追加
  - Microsoft Scripting Runtime
  - その他必要なライブラリ
- Excelファイル（.xlsm）の生成と保存

#### FR-004: 実行環境の簡素化
- バッチファイルによるワンクリック実行
- PowerShellの実行ポリシー考慮

### 2.2 非機能要件

#### NFR-001: パフォーマンス
- ビルド処理時間: 30秒以内（標準的なプロジェクトサイズ）
- Excelプロセスの適切な終了処理

#### NFR-002: 互換性
- OS: Windows 11
- Office: Excel 2016 / Microsoft 365
- PowerShell: 5.1以上

#### NFR-003: 保守性
- スクリプトの可読性とコメントの充実
- エラーハンドリングの実装
- ログ出力機能

#### NFR-004: セキュリティ
- VBAプロジェクトへの信頼アクセス設定の明示的な管理
- 実行権限の最小化

## 3. 制約事項

### 3.1 技術的制約
- Excel 2016の機能制限内での実装
- PowerShell実行ポリシーによる制限
- COMオブジェクトの制約

### 3.2 運用上の制約
- 初回セットアップ時のみ手動設定が必要
  - VBAプロジェクトへの信頼アクセス許可
  - PowerShell実行ポリシーの設定

## 4. 前提条件

### 4.1 環境前提
- Windows 11環境
- Excel 2016またはMicrosoft 365がインストール済み
- PowerShell 5.1以上が利用可能
- Gitがインストール済み（推奨）

### 4.2 開発者スキル前提
- 基本的なコマンドライン操作の知識
- VBAの基礎知識
- Gitの基本操作（推奨）

## 5. 成果物

### 5.1 納品物一覧
| 成果物ID | 成果物名 | 説明 |
|---------|---------|------|
| D-001 | Gitリポジトリ | 標準フォルダ構造を持つリポジトリ |
| D-002 | BaseTemplate.xltm | 基本テンプレートファイル |
| D-003 | Build-VbaProject.ps1 | ビルド自動化スクリプト |
| D-004 | build.bat | 実行用バッチファイル |
| D-005 | README.md | セットアップ・使用手順書 |

### 5.2 成功基準
- build.batの実行により、VBAコードが組み込まれた.xlsmファイルが自動生成される
- 生成されたファイルでVBAマクロが正常に動作する
- プロセスが30秒以内に完了する
- Excelプロセスが適切に終了する
